Haiku's failure was structural, not a matter of judgement — it wrote a regex the applier cannot execute. That is precisely what rules.Invalid exists to catch, and it did: the proposal became an escalation instead of an apply-time crash. The miss cost 32 rows on one patent.

Recommendation

  • Keep Haiku as the rule-tier default. It matches the frontier models on 7 of 8 layouts at a fraction of the price, and a rule is bought per layout (hundreds), so the tier's economics are dominated by token cost.
  • Opus is never worth it here. Byte-identical to Sonnet across all eight questions. Nothing in this run justifies its price on the rule tier.
  • Worth considering: retry once with Sonnet when a proposal raises Invalid. It fires only on structurally malformed proposals — rare, free the rest of the time — and would have recovered the 32 rows. The only evidence-backed improvement this run suggests.

What had to be fixed before the run meant anything

The harness had never compared models. Three independent defects, each individually sufficient to make the output vacuous, none of which changed how the output looked:

  1. repair_patent never passed a model to propose. The rule tier used SYNTH_MODEL regardless of the label. Haiku vs Haiku vs Haiku.
  2. A settled corpus asks nothing. Rules persist by layout fingerprint — that is the cost advantage over HARVEST — so every layout already had an answer. The first run measured asked 0, adopted 6: three identical replays of cached work. Fixed with --forget; _Snapshot still restores the library afterwards.
  3. gaps_for_patent fingerprinted raw tgroups while repair_patent fingerprints assembled blocks. The two disagreed about the identity of every multi-tgroup table, so --forget dropped 1 rule where production would consult 6. The same detector/extractor divergence classify_like_extractor exists to prevent, one level up.
And the cost meter: getattr(cost_tracker, "total_usd", 0.0) — the attribute is total_cost, so it returned the default on every run. A meter that reads zero when it is working and zero when it is not. It now reads total_cost and reports api_calls beside it, because a genuine $0 (everything cached) is otherwise indistinguishable from a broken one.
