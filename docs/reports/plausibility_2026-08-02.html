Why these checks don't use BindingDB

Every signal in gap.py scores rows produced. None can see a row that came out complete and wrong — and that class has cost more here than any coverage gap: 99 records once read 2.24 nM where the patent says 300 nM, with every count healthy, because a wrong unit produces records perfectly.

value_check catches those against BindingDB, which is the wrong dependency for a live check. BDB covers a fraction of what we extract, lags new patents entirely, and can say nothing at all about a compound it has never seen. A patent we get wrong in a way BDB cannot see is exactly the patent nobody will notice.

same_assay_disagrees is the one that matters. 2.24 nM is plausible in isolation; it is wrong only because the same assay reads 300 nM twelve rows earlier. Absolute bounds cannot see that, and a reference database should not have to.

99.8% land between 1e-2 and 1e4 nM. The window is set at 1e-3 to 1e6 — two orders wider on each side — because the job is catching a 1,000× unit error, not policing pharmacology: a real sub-picomolar binder must not be reported as a defect. The disagreement factor is 100×, since assay variability spans maybe 10× and the unit errors this exists to catch are 1,000×.

Framework

This is declarative data validation — the Great Expectations model: assertions about data, grouped into a suite, producing a validation result rather than raising. That shape is right and is what plausibility.py implements. The dependency is not: four checks over dataclass records do not justify adapting everything into DataFrames, and GX's value is its Data Docs and suite management, neither of which this needs. Pattern taken, library not.

The rescan half — flag, then let the model re-read the raw XML — is the evaluator-optimizer pattern, which Anthropic's guidance recommends only "when we have clear evaluation criteria." These four are exactly that: deterministic, cheap, and each names the function responsible.
