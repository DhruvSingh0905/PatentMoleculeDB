§ 2 Assay FSM core/assay_fsm/ + core/adaptive_extraction_cache.py

Five-component cascade. Top row: deterministic structural recovery (FSM) feeds an adaptive LLM realigner; the cross-validator emits typed AssayResult. HARVEST runs in parallel and contributes regex patterns to the library.

A discovered pattern stores {regex, column_assays, header_text, …} and fires by header anchor: structure and labels are decoupled. The regex is purely structural (a row shape like \d+\s+\d+\.\d+) and may match any patent; the column_assays are applied only when the pattern's header — its ordered, Greek-transliterated, punctuation-stripped column tokens — appears, in order and within a compact span, in the target patent's text. This check is evaluated once per pattern against the normalized text, so the decision depends solely on the text being processed. A pattern learned from a RORγ patent therefore re-fires for free on any other RORγ table (the scale win) but cannot fire on a Nav-channel patent that lacks that header (contamination is structurally impossible, not merely guarded). Because firing depends on the local header rather than a lifecycle counter, output is identical regardless of which patent discovered the pattern or in what order the corpus was processed — fully deterministic. The pending → auto_loaded → promoted counters remain as confidence signals only.

The realigner cache (adaptive_extraction_rules.json) is keyed on fingerprint_table_shape(headers, n_rows, sample_cells) scoped to patent_id; repeat passes over the same layout skip the LLM call.

§ 4 Image-recognition arm DECIMER + DECIMER-Seg + PaddleOCR

Two substrates feed one classifier. Sequential by design — DECIMER-Seg, DECIMER, and PaddleOCR are heavy local models; only one is held in memory at a time.

URL substrate · core/image_recog.py

Accepts Google's pre-cropped C#####.png URLs. Download → DECIMER → classify → emit Compound.

PDF substrate · core/image_cid_associate.py

Uses routes/decimer_segmentation_crop.segment_page(). Handles multi-structure figures and yields per-structure bboxes plus crops.

Shared classifier

image_recog.classify_decimer_output(raw) sorts every DECIMER prediction into complete, markush, or fail using two cheap signals — RDKit parseability with a reasonable MW, plus a pseudo-atom regex:

main = raw.split(".")[0].strip()
if validate_smiles(main) and 150 ≤ MW ≤ 1500:
    return "complete", main
if _RGROUP_TOKEN.search(raw) or "*" in raw:   # [R1] [X] [G] [W] [L] [Z] [Q] [A]
    return "markush",  main
return "fail",       main

CID association (PDF substrate)

Each structure crop is fed sequentially to DECIMER, then matched to its compound ID by an incremental directional expansion of its bbox. The search grows in small steps until a CID label is OCR'd; per-direction caps prevent reaching into the neighbouring row, and a distance metric resolves conflicts when two structures claim the same CID — the nearer keeps it, the other re-resolves.

Emitted records: provenance.route = "image_pipeline", provenance.stage = "decimer_local", source = EXEMPLIFIED, original crop retained in image_path. They merge into the same example_index.json the text arm writes, keyed by InChIKey so duplicates collapse.
